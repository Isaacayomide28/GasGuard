# Licensing and Third-Party Notices (Issue #1012)

## Objective

Keep an accurate inventory of every license shipped with GasGuard — our own and
third-party — and publish the notices required by those licenses alongside each
release.

## Repository license

GasGuard itself is licensed under [MIT](../LICENSE) (`LICENSE`, root of the repo).
Workspace packages that declare their own `license` field in `package.json`
(currently `apps/api-service`, `packages/cli`) also use MIT; packages without an
explicit field inherit the root license and should be updated to declare it
explicitly when touched.

## Scope

Notices must cover everything that ships to a user or operator, not just what's
installed in a developer's `node_modules`:

| Artifact | Source of dependencies | Notes |
|---|---|---|
| API service / worker (Node) | `apps/api-service`, `apps/api`, `libs/*`, `packages/*` `package.json` + resolved `node_modules` | Runtime + build-time deps bundled into `dist/` or the Docker image |
| Dashboard / web (Node) | `apps/web/package.json` + resolved `node_modules` | Ships to the browser; bundler output should be checked for license comments preserved by the build |
| Gas analysis engine (Rust) | `Cargo.lock`, `libs/engine`, `libs/rust` | `Cargo.lock` pins versions but carries no license metadata — resolved separately, see below |
| `gasguard-cli` binary (Rust) | `gasguard-cli/Cargo.lock` if present, else workspace `Cargo.lock` | Distributed as a standalone binary; same crate-license process applies |
| Docker images (`docker-compose.yml`: `postgres`, `redis`, `api`, `worker`, `dashboard`) | Base image vendor notices (Debian/Alpine, Postgres, Redis) | Pull the base image's own `/usr/share/doc/*/copyright` or vendor notice; not regenerated by our scripts |
| `lib/forge-std` git submodule | Upstream [foundry-rs/forge-std](https://github.com/foundry-rs/forge-std) | Apache-2.0 OR MIT upstream; re-verify against the checked-out submodule before each release since it's not vendored into our license scan |

## Generating notices

Two scripts produce the notices; run both before cutting a release:

```bash
# npm/pnpm packages across the workspace -> THIRD_PARTY_NOTICES.md
pnpm install   # required for full resolution; without it only direct deps are listed
node scripts/generate-third-party-notices.mjs
# or: pnpm run license:notices

# Rust crates resolved via Cargo.lock -> RUST_THIRD_PARTY_NOTICES.md
cargo install cargo-license   # one-time
bash scripts/generate-rust-license-notices.sh
```

Both outputs are generated files — do not hand-edit them. Re-run the scripts and
commit the diff instead.

`scripts/generate-third-party-notices.mjs` walks `node_modules` when present (giving
exact resolved versions and license identifiers for the full dependency tree,
including transitive packages) and falls back to the direct dependencies declared
in each workspace `package.json` when `node_modules` is absent, flagging those rows
as unresolved so a stale/incomplete notice file is never mistaken for a complete
one.

## Review triggers

Regenerate and review notices when:

- Cutting a release (see [UPGRADE_ROLLBACK_RUNBOOK.md](UPGRADE_ROLLBACK_RUNBOOK.md) prechecks)
- Adding, removing, or bumping a dependency with a different license than before
- Adding a new shipped artifact (new app, new Docker image, new binary target)

A license that is not MIT-compatible (e.g. copyleft licenses such as GPL/AGPL, or
anything requiring source disclosure for a hosted service) found in a *runtime*
dependency blocks the release until legal/triage signs off or the dependency is
replaced. Build-only / dev-only tooling is lower risk but should still be recorded.

## Ownership

Whoever bumps a dependency is responsible for confirming its license did not
change and for regenerating `THIRD_PARTY_NOTICES.md` in the same PR when it did.
Final sign-off on notice completeness for a release is a release-manager
responsibility per the upgrade runbook.
